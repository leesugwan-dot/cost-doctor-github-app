# CostDoctor 공개 라이선스 선택 가이드

상태: `DECISION_REQUIRED / LICENSE_NOT_SET`

라이선스는 기술 문제가 아니라 공개 코드의 재사용 권리를 결정하는 항목이라 자동 확정하지 않습니다.

## 추천

**공개 GitHub 연동·진단 계층: Apache-2.0**  
**상용 최적화 핵심: 별도 비공개 유지**

이 조합을 추천하는 이유:

- 공개 진입부를 사용자가 검토·신뢰하기 쉬움
- 기업 사용에 비교적 익숙한 허용형 라이선스
- 특허 관련 조항이 MIT보다 명시적
- 상용 핵심까지 모두 공개할 필요 없음

## 다른 선택지

### MIT

가장 단순하고 허용 범위가 넓습니다. 타사가 공개 코드를 상업 서비스에 재사용하는 것도 매우 자유롭습니다.

### GPL 계열

수정·재배포 시 소스 공개 의무가 강해질 수 있습니다. 공개 생태계에는 유리할 수 있지만 일부 기업 도입 장벽이 될 수 있습니다.

### Proprietary only

공개 코드를 거의 허용하지 않는 방향입니다. 현재 이미 공개된 GitHub 진입계층의 신뢰·확산 목표와는 덜 맞습니다.

## 결정 후 자동 적용 가능한 작업

사용자가 라이선스를 확정하면 다음은 자동 처리할 수 있습니다.

- `LICENSE` 파일 추가
- README 라이선스 표시
- 공개/비공개 경계 문서 갱신
- Marketplace 초안과 기여문서 갱신
- 라이선스 회귀검사 추가

이미 공개된 과거 버전의 권리관계에 영향을 줄 수 있으므로 라이선스 선택은 운영자 승인 없이 자동 적용하지 않습니다.
