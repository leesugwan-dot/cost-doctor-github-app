# CostDoctor 결제·수익화 정책 초안

상태: `DRAFT_ONLY / BILLING_DISABLED`

## 추천 원칙

무료 공개 진단은 계속 무료로 유지하고, **실제 가치가 Evidence로 증명되는 단계**부터 유료화합니다.

### 무료

- 공개 GitHub URL 정적 진단
- private repository Self-Scan용 읽기 전용 workflow
- 정적 신호와 다음 확인사항
- 실제 절감액 Evidence가 없으면 `UNKNOWN`

### 유료 후보 1 — Verified Fix

고객이 선택한 문제에 대해:

- 개선안 생성
- 실제 테스트
- Before/After 비교
- 품질/회귀검증
- 독립 검증
- rollback 준비
- 사용자 승인 시 PR 생성

### 유료 후보 2 — 반복 모니터링

검증된 프로젝트에 한해 일정 주기 또는 변경 시 비용/토큰 회귀를 확인합니다.

## 추천 과금 방식

초기에는 복잡한 사용량 종량제보다 **건별 Verified Fix**가 적합합니다.

이유:

- 실제 효과 Evidence와 가격을 연결하기 쉬움
- 아직 반복 사용량 데이터가 없는 단계에서 월 구독 가격을 임의로 정하지 않음
- 고객이 "무엇에 돈을 냈는지" 이해하기 쉬움

외부 사용성·반복 사용 Evidence가 쌓이면 월 구독 또는 팀 플랜을 검토합니다.

## 아직 숫자로 고정하지 않는 항목

- Verified Fix 가격
- 월 구독 가격
- 무료 사용 한도 변경
- 환불 기준
- 지원 응답시간
- 기업 플랜

실제 외부 사용자 가치와 운영비 Evidence 없이 숫자를 고정하지 않습니다.

## 비용 실행 경계

실제 LLM/API Before/After 측정이 필요한 경우 추천 구조는 **고객 자신의 GitHub Secret + 고객 API 계정**입니다.

- API Key를 공개 Issue나 채팅에 입력하지 않음
- CostDoctor 운영자의 개인 PC로 비밀키를 전달하지 않음
- 비용이 발생하는 실행 전에 고객이 해당 실행과 지출 한도를 승인
- 승인된 한도를 넘기지 않음

## 환불정책 추천 방향

유료화 시 다음처럼 단순하게 시작하는 것을 추천합니다.

- 결제 전 작업 범위와 측정기준 명시
- 실제 실행 전 취소 가능 여부 명시
- 기술적 실패로 약속한 Verified 결과를 제공하지 못한 경우 환불 또는 재실행 원칙
- '절감률 보장' 같은 근거 없는 성과보장은 하지 않음

최종 환불·세금·사업자 표시·전자상거래 관련 문구는 운영자와 관할 법률 기준으로 확정해야 합니다.
